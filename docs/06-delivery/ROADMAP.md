## Next (recommended order, not yet started)

1. **Business validation** — confirm merchant and customer interest in Badarpur before more
   engineering (see [`../00-project/PRODUCT-VISION.md`](../00-project/PRODUCT-VISION.md)). This is
   a business task, not a coding task, and can run in parallel with the items below.
2. **BC-009 commit/CI verification** — the owner reviews the working tree, authorizes commit and
   push, and its integration suite is confirmed against CI's real Postgres, then it's closed out
   the same way BC-004 through BC-008 were.
3. **Notification dispatch worker** — a consumer of `outbox_events` that actually delivers the
   `ORDER_READY_FOR_PICKUP`/other events to a device (FCM or an equivalent push/SMS channel) -
   BC-009 implements the transactional write only, deliberately decoupled from delivery. See
   `PICKUP-WORKFLOW-DESIGN.md`'s "Notifications" section and `TECHNICAL-DEBT.md`.
4. **Admin operational controls** — a configuration screen for `commission_percent`/delivery-fee
   rules (FR-ADM-002, still Planned). BC-010 implemented the delivery-fee _accounting_
   (`COD-DELIVERY-RECONCILIATION-DESIGN.md`) and the full delivery-assignment workflow
   (`DELIVERY-MANAGEMENT-DESIGN.md`) the roadmap had bundled under this item's old name
   ("Delivery, and admin controls") - the commission/fee _configuration UI_ itself remains open.
5. **Security remediation task** — resolve the `react-router-dom` production vulnerability and
   evaluate the Vite/Vitest major-version upgrade (see
   [`../08-quality/RISK-REGISTER.md`](../08-quality/RISK-REGISTER.md)). This can run independently
   of the above, whenever convenient.
6. **Public store/product-listing endpoint** — BC-011 Stage 1 confirmed no customer-facing "browse
   stores"/"browse a store's products" endpoint exists. This blocks the customer Home and Store
   Catalogue screens (and the already-built `StoreCard`/`ProductCard` components sitting unused);
   recommended next after BC-011's remaining screen migration.
7. **BC-011 continuation** — migrate the Merchant POS Terminal, Merchant Inventory/Settings/
   Analytics, Admin Merchant Approvals, Admin Delivery Queue and Delivery Partner Inbox screens
   onto the design system built in BC-011 Stage 2-3.

Each numbered item above should become its own task in
[`TASK-TRACKER.md`](TASK-TRACKER.md) with requirement references, rather than being executed as
one large undifferentiated effort — see the mandatory workflow in [`AGENTS.md`](../../AGENTS.md).
